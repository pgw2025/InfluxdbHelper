# InfluxdbHelper 前后端分离迁移方案

> 技术选型：Vue 3 + Vite + TypeScript + Element Plus ｜ ASP.NET Core 8 Web API + JWT
> 迁移策略：渐进式（旧 Razor Pages 保留对照，全部迁移完成后再移除）
> 部署方式：Nginx 托管前端静态文件 + 反向代理 `/api` 到后端

---

## 一、目标架构

```
InfluxdbHelper.sln
├── InfluxdbHelper.Core/            # ★ 新增：业务类库（net8.0 类库项目）
│   ├── Services/                   #   InfluxDBService / StatisticsService / DingTalkService
│   ├── Models/                     #   InfluxDBConfig / DingTalkConfig / FormModel
│   ├── DTOs/                       #   StatisticsDto 等
│   └── BackgroundServices/         #   DailyStatisticsNotificationService
│
├── InfluxdbHelper/                 # 现有 Razor Pages 项目（过渡期保留，改为引用 Core）
│   └── Pages / wwwroot             #   旧版继续可用，作为对照
│
├── InfluxdbHelper.Api/             # ★ 新增：纯 Web API 项目
│   ├── Controllers/                #   Auth / System / Config / Statistics / Variables
│   ├── Program.cs                  #   JWT + Swagger + CORS + 统一响应
│   └── appsettings.json            #   复用现有配置节结构
│
└── influxdb-web/                   # ★ 新增：Vue3 前端（独立 npm 工程，不入 .sln）
    └── src/
        ├── api/                    #   axios 封装 + 各模块接口
        ├── stores/                 #   Pinia：user / config
        ├── router/                 #   路由 + 登录守卫
        ├── layout/                 #   侧边栏 + 顶栏布局
        └── views/                  #   login / dashboard / statistics / history / config
```

**核心思路**：业务逻辑已经全部在 Services 层，与页面解耦良好。抽成 `Core` 类库后，旧 Web 项目和新 Api 项目共享同一份业务代码，迁移期间两边行为完全一致，随时可回退。

## 二、后端设计（InfluxdbHelper.Api）

### 2.1 API 接口规划

| 控制器 | 接口 | 说明 | 迁移自 |
|---|---|---|---|
| AuthController | `POST /api/auth/login` | 用户名密码换 JWT | 新增 |
| | `GET /api/auth/profile` | 当前用户信息 | 新增 |
| SystemController | `GET /api/system/status` | InfluxDB 配置状态 + 连接检测 | Index.cshtml.cs OnGet |
| ConfigController | `GET /api/config` | 读取当前配置（Token 脱敏） | Config OnGet |
| | `PUT /api/config` | 保存配置（可选写回 appsettings.json）+ 热重载客户端 | Config OnPostAsync |
| | `POST /api/config/test` | 仅测试连接，不保存 | Config 拆分 |
| StatisticsController | `GET /api/statistics?period=day&start=&end=` | 总量 + 各变量统计 | Statistics/Index OnGet |
| | `GET /api/statistics/history` | 变量历史分页查询（page/pageSize） | VariableHistory OnGet |
| VariablesController | `GET /api/variables/autocomplete?q=` | 字段名联想（已有） | 现有 |

### 2.2 JWT 认证

- 包：`Microsoft.AspNetCore.Authentication.JwtBearer`
- 单用户/少量用户直接放 `appsettings.json`（密码存 SHA256 哈希），无需数据库；将来多用户再升级
- `/api/auth/login` 验证后签发 token（有效期 8h，可配置），Claims 带 `sub` / `role`
- 除 `login`、`/api/auth` 外全部接口挂 `[Authorize]`
- 401 由前端 axios 拦截器统一捕获 → 跳转登录页

### 2.3 统一响应与异常

```jsonc
// 成功
{ "code": 0, "message": "ok", "data": { ... } }
// 失败
{ "code": 1001, "message": "InfluxDB 连接失败: ...", "data": null }
```

- 全局异常过滤器，替代现在 `catch { return Page() }` 的静默吞错模式
- Swagger（Swashbuckle）开发环境启用，带 Bearer 授权按钮

### 2.4 CORS

开发环境放行 `http://localhost:5173`（Vite 默认端口）；生产走 Nginx 同域反代，无需 CORS。

### 2.5 BackgroundService

`DailyStatisticsNotificationService` 原样迁到 Api 项目，钉钉推送逻辑不变。

## 三、前端设计（influxdb-web）

### 3.1 技术栈

- Vue 3.4+（`<script setup>` 组合式 API）
- Vite 5 + TypeScript
- Element Plus（按需自动导入：`unplugin-vue-components` + `ElementPlusResolver`）
- Vue Router 4（`createWebHistory`）+ 路由元信息守卫
- Pinia（user store 存 token，持久化到 localStorage）
- Axios（实例封装：请求带 Bearer、响应解包、401 跳登录、ElMessage 错误提示）
- ECharts 5（统计页图表，可选增强项）

### 3.2 页面清单

| 路由 | 页面 | 对应旧页面 |
|---|---|---|
| `/login` | 登录页 | 新增 |
| `/` | 仪表盘（InfluxDB 状态卡片 + 快捷入口） | Index.cshtml |
| `/statistics` | 数据统计（周期切换 / 自定义时间 / 变量分布表格+图表 / 明细下钻） | Statistics/Index.cshtml |
| `/history` | 变量历史查询（变量名联想 + 时间范围 + 分页表格） | VariableHistory.cshtml |
| `/config` | 系统配置（InfluxDB + 钉钉 + 推送模板，"保存并测试"按钮） | Config.cshtml |

### 3.3 关键交互升级（相对旧版）

- 分页从"URL 参数整页刷新"改为前端分页组件 + 接口参数化，体验大幅提升
- Config 保存后的 TempData 提示 → ElMessage / ElNotification
- 变量历史表格支持列排序、导出 CSV（前端完成，无后端成本）
- 统计页加 ECharts 柱状图展示各变量数据量分布

## 四、开发与部署

### 4.1 开发期（本地联调）

`vite.config.ts` 代理，前后端各自启动：

```ts
server: {
  proxy: {
    '/api': { target: 'http://localhost:5100', changeOrigin: true }
  }
}
```

- 后端：`dotnet run --project InfluxdbHelper.Api`（端口 5100）
- 前端：`npm run dev`（端口 5173）

### 4.2 生产部署（Nginx）

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态文件
    root /var/www/influxdb-web/dist;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }   # SPA history 路由回退

    # API 反代到 Kestrel
    location /api/ {
        proxy_pass http://127.0.0.1:5100;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

后端用 systemd / Windows 服务 / IIS 反代托管均可。同域反代 ⇒ 无 CORS、无 Cookie 跨域问题。

## 五、迁移步骤（建议按序执行，每步可独立验证）

| 阶段 | 内容 | 验证点 |
|---|---|---|
| **1. 抽 Core 类库** | 新建 `InfluxdbHelper.Core`，Services/Models/DTOs/BackgroundServices 平移；旧项目改为引用 Core 并删除本地副本 | 旧 Razor Pages 功能一切照旧 |
| **2. 搭 Api 骨架** | 新建 `InfluxdbHelper.Api`：JWT + Swagger + CORS + 统一响应 + 全局异常；迁 AuthController + SystemController | Swagger 调通登录和状态接口 |
| **3. 业务接口** | 迁 Config / Statistics / Variables 控制器，把 PageModel 逻辑改为返回 DTO | 用 Swagger 逐接口对照旧页面数据 |
| **4. Vue 骨架** | Vite 脚手架 + Element Plus + Router 守卫 + Pinia + axios 封装 + 登录页 + 布局 | 登录跳转仪表盘 |
| **5. 逐页迁移** | Dashboard → Statistics（含 ECharts）→ History（联想+分页）→ Config | 每页与旧版数据一致 |
| **6. 收尾** | Nginx 部署配置、`appsettings.Production.json`、删除旧 Pages/wwwroot、卸载 RazorPages 依赖 | 生产环境全流程回归 |

## 六、风险与注意事项

1. **Config 写 appsettings.json**：生产环境容器/受限目录可能只读，`PUT /api/config` 需保留"仅内存生效"选项（现有 `SaveToConfigFile` 语义）。
2. **InfluxDB Token 脱敏**：`GET /api/config` 返回 Token 时应打码（如 `****last4`），前端留空表示不修改。
3. **时区**：旧代码混用 `DateTime.Now` 与 UTC（NodaTime），接口统一返回 ISO 8601 带时区偏移，前端用 dayjs 解析。
4. **依赖注入差异**：Core 类库中 `ReinitializeClientAsync` 依赖 `IConfiguration` 热重载，Api 项目需保证配置节名称完全一致。
5. **JWT 密钥管理**：`Jwt:Key` 放 `appsettings.Production.json` / 环境变量，至少 32 字符。
